# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static personal portfolio website (Jevan Hava Maula Ihsan) — plain HTML/CSS/JS, no build step, no package manager, no test suite. Pages are opened directly as files or served via any static file server; there is no dev server command to run.

## Repository layout

- Root (`index.html`, `styles.css`, plus one folder per page — `about/`, `work/`, `leadership/`, `projects/`, `social-projects/`, `awards/`, `skills/`, `project-python/`, `python-part1/`–`python-part4/`, `gallery-*/` — each holding an `index.html`) — the live site content. Treat this as canonical when editing. Pages use clean URLs (e.g. `/about/`, no `.html`); internal links between pages are `../<page>/` from inside a page folder and `<page>/` from root `index.html`, and asset/stylesheet links from inside a page folder need a `../` prefix (`../styles.css`, `../assets/...`).
- `Preview/` — a near-mirror of the root site kept manually in sync (via plain `cp` — see `.claude/settings.local.json` allowed commands). Most page files here are byte-identical to root; `styles.css` and some pages have drifted slightly, so **when editing shared content/styles, check whether the same change needs to be mirrored into `Preview/` and reconcile drift rather than assuming the two are identical.**
- `codes/` — older/reference copies of the gallery pages plus `gallery-template.html`, the base template new gallery pages are derived from. These are not the live pages (compare against root before assuming `codes/` reflects current markup).
- `assets/charts/` — PNG chart images generated by the Python scripts in `Preview/` (`generate_ex_charts.py`, `generate_html_details.py`). These scripts read data from an external local path (`~/Documents/CFI /BIDA/12. Python Data Analysis/...`) outside this repo and write chart PNGs to **both** `Preview/assets/charts/` and `assets/charts/` — keep both in sync if regenerating charts.
- `assets/gallery/<name>/` — per-experience media folders (askrindo, impactional, leadership, neurolima, python, wavery) referenced by the corresponding `gallery-*.html` pages.
- `python-data-analysis.md` / `python-walkthrough-draft.md` — source writeups that `generate_html_details.py` parses (splits on `## Part N:` headers) to help assemble the `python-part*.html` walkthrough pages and inline chart captions.

## Page/template conventions

- Each top-level page repeats the same `<nav>`/hero/footer scaffold and a scroll-progress bar (`#prog`) with hamburger menu JS inlined at the bottom of the file — there's no shared layout include, so structural nav changes must be repeated across every page.
- Gallery pages (`gallery-<company>.html`) follow the structure in `codes/gallery-template.html`: a `g-header` block (label/title/dates) plus a `g-content` placeholder grid, styled via the shared `.g-*` classes in `styles.css` (not scoped per-page in current root versions — earlier `codes/`/`Preview/` versions used inline `<style>` blocks instead, which is why they diverge from root markup).
- Design tokens (colors, radius) are CSS custom properties: `--navy`, `--gold`, `--muted`, `--border`, `--bg`.
